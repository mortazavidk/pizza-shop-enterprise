# IS Detective V6 — Unique Student Challenge Assignments

## Deploy
Upload `index.html`, `style.css`, and `app.js` to a public GitHub Pages repository root. Use Settings → Pages → Deploy from branch → main → /(root).

## Instructor setup
Use `INSTRUCTOR_ASSIGNMENTS.csv` **privately** to distribute one assignment code per student. Section A has A01–A35; Section B has B01–B33. **Do not upload the instructor CSV to GitHub Pages.** Students enter their name and assigned code on the home page. The code determines and locks the role and department and generates a distinct six-incident assignment. Each student gets six challenge cases, each with a different incident ID, shop/shift context, numerical observations, and shuffled answer order. Four common practice cases are retained.

## How evidence exchange works
An investigator tells a department representative their **assignment code** and **case number**. The representative opens Problem Evidence Card, enters the investigator's assignment code, selects the case, and sees facts from **their own locked department** for that specific investigator incident. The representative shares the evidence IDs verbally and records the exchange. The investigator records at least two IDs from different departments and a written explanation before submitting.

## Scoring
For each challenge: first fully correct submission 10, second 3, third 0. Locked after three attempts. Maximum 60. Download a student score CSV from the home page. Browser progress is stored locally; reset clears it.

## Important limitations
GitHub Pages is static. Assignment codes are **not passwords** and cannot prevent students from using the same code on another device or inspecting source code. Unique assignments are achieved by distributing codes uniquely, not by server-enforced reservation. Each student's incident is individually contextualized and has shuffled answer positions, but six underlying problem archetypes are reused; sharing conceptual solutions is still possible. Evidence exchange is face-to-face and not synchronized. For true access control and live instructor scoreboards, a backend is required.
